Every pull request Aperture Agent Check runs on can now say so where reviewers look. The run's summary opens with a **Checked by Aperture** badge that links the pull request on Aperture's public checker, and with `comment: true` Agent Check keeps one comment on the pull request with the badge, the verdict and a line per check, updated on every push. The checks themselves got fairer: `/check` no longer calls valid TypeScript broken, imports resolve the way TypeScript resolves them, and on the same 137 agent pull requests as the proof run, 6 are red instead of 32, with the same 5 real catches. A red result now fits on a phone.

This release has no database migration. Aperture Agent Check and Aperture Bot bundle the import resolution, type check and tests rule that changed, and Agent Check the badge and the comment, so both are rebuilt from this release: Agent Check v1.10 and Aperture Bot v1.22. The badge appears once Agent Check v1.10 is out; the comment needs `comment: true` and `pull-requests: write` in the workflow.

### Added

- **Checked by Aperture, on the pull request.** Agent Check's run summary now opens with a badge, green "nothing red" or red "held back", that links the pull request on Aperture's public checker. With `comment: true` (and `pull-requests: write`), it also keeps one comment on the pull request with the badge, the verdict and a line per check, updated in place on every push so it never piles up. It is off by default, being the one thing the action sends anywhere, to GitHub's own API with the workflow's token; without the permission, or on a fork's pull request, the run says so and the checks stand. The Bot page's Check tab hands out the workflow with the comment on, saying what each line does ([#277](https://github.com/Hankaws/aperture/pull/277)).

### Changed

- **The release check reads what an action was built from in its notes,** which "Build from Aperture" writes from the commit it actually built. A build that changes no file makes no commit, so its tag lands on the previous build commit, and reading that commit's message called Agent Check v1.9 and Aperture Bot v1.21, built from v0.34.0, stale on every daily run. A tag that is not on a build commit is still a failure ([#274](https://github.com/Hankaws/aperture/pull/274)).

### Fixed

- **`/check` stops calling valid code broken.** Before a parse error turns a check red, TypeScript's own parser must agree, so `catch (e: unknown)`, `let x!: T`, `<Form<Dto>>`, generic arrow functions, `export default interface`, import attributes and JSX in `.js` files pass; a real syntax error still goes red and now says what is wrong ("Merge conflict marker encountered", "'catch' or 'finally' expected"). Imports resolve the way TypeScript does: tsconfig `paths` are read from the package's own tsconfig, relative to its `baseUrl` (`@/x.js` finds `src/x.ts`), and a bare import is looked for under `baseUrl` before it is called an undeclared package. An imported image is there even though its bytes are not text, a name declared in the `.d.ts` beside a `.js` file is exported, and a file in a build or code generator's output (`dist/`, `__generated__/`) is not called missing. Past the import limit, a missing import is not judged at all. The light Types check reads `let a = 0, c: string[] = []` one name at a time and no longer reports `string` in a generic call as a missing name. The tests rule lets a `&&` test script gain a step (worth a look, not red), and no longer holds `process.exit(1)` in a test or a clean exit in a script with a `#!` line. The page reads the whole description, so Claude Code's pull requests are named as its, and a draft shows as open. Re-run on the same 137 agent pull requests as the proof run: 6 red instead of 32, with the same 5 real catches ([#276](https://github.com/Hankaws/aperture/pull/276)).
- **A red result fits on a phone.** A red result no longer crowds out the code. The check strip is capped at under half the screen and scrolls on its own, so the code and the bar with the verdict and **Send back** stay on screen above the tab bar; before, the code shrank to nothing and the bar was pushed under the tabs. Three text colours now clear 4.5:1: function names in the light theme's code on a deleted line, the caption under the landing page's demo, and the line under "Make your first bot" on the Bot page. The test of the /agent-check example no longer depends on whether Node prints a failing test as `not ok` or `✖`, so it passes on Node 22 and 24 ([#275](https://github.com/Hankaws/aperture/pull/275)).
